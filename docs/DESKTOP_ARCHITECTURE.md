# Desktop architecture and milestone status

## Runtime boundary

The installed application is authoritative. `apps/desktop-ui/dist` is bundled by Tauri as `frontendDist`; no product page, PWA, service worker, Cloudflare Worker, D1 binding, or browser authentication helper remains. The cloud API is optional and cannot generate the offline plan.

## Local data boundary

The Rust host opens `student-center.db` with SQLCipher and a 256-bit random device master key stored in the operating-system credential service. Imported source files are copied into the app data vault and encrypted with XChaCha20-Poly1305 under unique object keys, which are then wrapped by the device key. Only typed commands are exposed to the React webview.

An optional application PIN adds a second local privacy gate for an already signed-in OS session. A versioned `pin.json` stores Argon2id parameters, a random salt, and an XChaCha20-Poly1305-wrapped copy of the device master key; it contains neither the PIN nor plaintext key. Settings replacement is staged and recoverable, Argon2 work runs off the UI thread, failed unlocks use increasing delays, and a PIN-enabled restart begins locked. Startup returns only security status until unlock succeeds, and every data-bearing Tauri command independently checks the locked state. The database connection and OS-protected key remain resident in the native process, so this gate is intentionally an app privacy control rather than a defense against code executing as the same operating-system user.

The append-only `mutations` table records UUID mutation IDs, logical timestamps, device IDs, operations, and tombstones. This is the local source for future E2EE push/pull. Normalization produces `import_candidates`; only explicit approval creates or updates canonical records. Field-level `provenance_links` retain the active source evidence for imported critical values.

After optional account sign-in, sync protection is established entirely in Rust. New protection generates a random 256-bit account key and encodes it as a checksummed 24-word English BIP-39 recovery code. The student must confirm three unique randomly selected words before anything persists. Recovery validates all 24 words and the checksum locally. Every setup or recovery also creates a separate random X25519 device private key and UUID; only the public key and non-sensitive status can cross the Tauri IPC boundary. Pending keys use zeroizing native memory, and confirmed account/private device keys are stored as one versioned record in the operating-system credential vault rather than SQLite or browser storage. Device registration, encrypted mutation transport, approval envelopes, and revocation remain separate network steps.

Portable backups use a versioned tar stream inside age passphrase encryption. The payload contains a transactionally consistent SQLCipher snapshot, the prior device key only inside the encrypted envelope, authenticated manifest hashes, and vault objects that are already independently encrypted. Preview consumes and authenticates the whole archive, rejects unknown/duplicate/traversal entries and size abuse, and returns a ciphertext SHA-256 fingerprint. Restore requires that same fingerprint and a second explicit confirmation, validates every document by decrypting it in memory, rewraps each object key, rekeys SQLCipher to the current OS-protected device key, and stages all data before replacing anything. A small restore journal rolls back to the previous database and vault after interruption; successful installation removes the journal before deleting rollback material. Credentials are never exported, and Canvas connections return as `needs_reauthentication`.

## Completed in Milestone 1

- Honest first run in schema version 7: production startup no longer seeds a student, course, commitments, tasks, or plan. Fresh profiles receive a six-step offline onboarding flow; upgraded 0.2.0 profiles receive an explicit, exact-match demo cleanup review with no automatic deletion.
- Versioned local `StudentProfile`, `AcademicTerm`, `PlanningPreference`, weekly availability, course, detailed task, dependency, and commitment fields. Profile migrations use a rollback savepoint, repair the legacy manual-course uniqueness constraint, and are idempotent across interrupted/repeated startup.
- Typed, lock-gated native CRUD for terms, courses, detailed tasks, commitments, availability, and planning preferences with optimistic version checks. Calendar and Academics expose real local records, editors, and empty states rather than inert navigation.
- Explicit local profile deletion with a pre-deletion encrypted-backup path, exact confirmation phrase, transactional database clearing, recoverable vault replacement, and return to onboarding.
- Fully bundled React/Tauri application and native file dialogs.
- Encrypted local database, migrations, key protection, and encrypted vault.
- Manual tasks, fixed commitments, deterministic planning, next action, completion, and late-change replanning.
- Content-signature validation, encrypted source deduplication, and visible extraction status/failure reporting.
- Local text PDF, text, DOCX, PPTX, CSV, and XLSX extraction with evidence review.
- Deterministic ICS recurrence, timezone, DST, and exception expansion into reviewable commitments.
- Image/scanned-PDF OCR command adapters, confidence-aware evidence parsing, Tauri resource discovery/readiness reporting, native-process time/page/output limits, and a deterministic critical-date golden fixture.
- Local Canvas personal-token connection, manual refresh/disconnect, active course/assignment/calendar pulls, immutable source snapshots, review candidates, explicit critical-date conflict resolution, and local sync history. Accepting a source change updates the linked canonical record in place and rotates active field provenance; keeping the current value rejects only that snapshot. The transport rejects non-HTTPS origins, IP literals, credentials, paths, custom ports, private/reserved DNS answers, redirects, proxies, oversized responses, and pagination that leaves the validated origin. Canvas tokens live in the native OS credential vault and are never returned to the webview.
- Ciphertext sync schemas and cloud route skeletons.
- Managed OpenAI structured-output endpoint with content-redacted logs and `store: false`.
- Supabase JWT verification through the project's asymmetric JWKS, account identity derived exclusively from the verified token, a PostgREST-backed ciphertext repository that preserves user RLS, and migrations for devices, immutable encrypted mutations, approval envelopes, encrypted object manifests, a private chunk bucket, and account-isolation policies. Mutation IDs are idempotent but cannot be reused with different ciphertext.
- Native email one-time-code and Google sign-in with compile-time Supabase trust configuration. Google uses a random 43-character PKCE verifier, SHA-256 challenge, five-minute `sb_flow_id` correlation, the system browser, an exact `studentcenter://auth/callback` allowlist, and native code exchange. Redirects, fragments, duplicate/unknown callback fields, stale flows, mismatched flow IDs, and encoded delimiter injection are rejected. Strict no-redirect HTTPS requests, a local email resend guard, serialized refresh-token rotation, and local-scope sign-out complete the session boundary. Only the refresh token plus minimum account identity are persisted in Windows Credential Manager or macOS Keychain; access tokens remain in native-process memory and no token, OAuth code, verifier, or authorization URL is serialized to the webview. Invalid stored session records are discarded without affecting the local profile.
- Confirmed 24-word BIP-39 recovery setup and recovery, random per-device X25519 identity generation, zeroizing pending-key memory, OS-credential-vault persistence, locked-state authorization, and a React confirmation/recovery flow that receives no secret private key material.
- Native device registration and encrypted mutation push. The profile binds to one account only after authenticated registration succeeds. Mutation plaintext is encrypted with XChaCha20-Poly1305 under the account key; protocol version, mutation/account/device/entity IDs, logical timestamp, entity type, schema version, and tombstone flag are authenticated as associated data. Ciphertext envelopes are written to an encrypted local outbox before upload and reused byte-for-byte until acknowledged, preventing crash retries from reusing a mutation ID with a different nonce/ciphertext.
- Cursor-based encrypted pull and local decryption. Every downloaded envelope must authenticate under the account key and expected account metadata before its cursor advances. Duplicate mutation IDs must retain byte-identical envelopes. Mutations already present locally are acknowledged; remote mutations are staged in SQLCipher with `applied=0` until their entity type has a deterministic merge rule, and this pending state is visible in the account interface.
- Windows private-beta installer build and Windows/macOS CI lanes.
- Encrypted portable export, authenticated preview, explicit restore confirmation, cross-device database/object-key rekeying, and interruption rollback.
- Optional Argon2id Student Center PIN with enable, change, disable, lock-now, startup lock screen, throttled failures, atomic settings recovery, and locked-state command authorization.
- Opt-in native reminder delivery with encrypted preferences/history, timezone-aware quiet hours, generic locked-screen content by default, and in-app Start, Complete, Snooze, and Dismiss actions. Tauri desktop does not expose native toast action buttons, so the interface does not claim unsupported OS behavior.
- Strictly allowlisted plan-block/My Day deep links, pending-target preservation across the PIN gate, single-instance forwarding, main-window focus, and automatic window-state persistence.
- Fail-closed signed updater checks through the Rust boundary. The HTTPS release endpoint and Tauri public verification key are compile-time trust anchors; normal development/CI builds have no update channel, expose no updater permissions to the webview, and cannot install an update. Release-only updater artifacts are enabled by the separate `tauri.release.conf.json` overlay and require signing secrets outside the repository.

The Windows release executable and NSIS artifact now bundle and pass the real PDFium-to-PNG-to-Tesseract smoke path. Supply-chain selection is complete: immutable hashed PDFium archives replace Poppler, Tesseract 5.5.2 is built statically from a pinned vcpkg baseline, signed official English trained data is pinned, transitive notices are collected, and each desktop CI lane enforces a source-bound runtime lock before packaging.
- Deterministic apply/merge integration, approval/revocation UX, encrypted object chunk endpoints, signed device envelopes, richer mergeable mutation payloads, and two-device convergence tests.
- Accessibility and installed-app end-to-end coverage on both target platforms.

An injected in-memory repository is retained only for deterministic API contract tests. The SQL/private-bucket migration is present but still requires deployment validation against a real Supabase project before synchronization is released.
