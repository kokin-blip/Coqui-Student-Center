# Seven student workflows: implementation and verification

Status: code implemented; release certification has outstanding checks below. Changes are uncommitted in the current checkout. No enrollment changes or production grade approvals were performed.

## Reviewable increments

1. **Semester import boundary.** A document-specific native preview returns extraction state, OCR readiness, and evidence candidates, including duplicate sources. Byte-selected PDFs are materialized temporarily for local scanned-PDF rendering. Selected files, paths, drop, and paste share the preview boundary; native content detection remains authoritative. Existing `Uint8Array` transport is retained: a transport incompatibility was not reproduced. Imports produce unsaved schedule ideas, with editable course/time matches and retained source evidence.
2. **Today and Semester hierarchy.** Task rows have one primary completion action, inline earlier-completion controls, secondary outcomes and rescheduling. Time conversion uses the saved timezone; nonexistent and repeated daylight-saving times need correction or explicit occurrence choice. Failures preserve entered data; success announces persistence and advances focus. Streak rules and history remain accessible under an inline summary. Semester leads with deterministic findings and missing-data caveats, with detail and import controls in disclosures. A scoped Inter override corrects the existing unbundled Manrope heading rule.
3. **Learn.** Single-course selection leads the page. Recommendations, supporting materials, and grounded practice/questions form the main flow. Empty courses have one Add materials action; revision, saved tools, multi-course scope and optional AI reranking are secondary. Existing models, tabs and exact-scope consent are reused.
4. **CSV grades.** Course-scoped preview accepts assignment rows and Canvas assignment columns. Multi-student exports require explicit selection. Column mapping, corrections, blanks versus zero, categories, duplicates, confidence and evidence remain visible. Apply runs one native transaction with gradebook and draft revision checks. Failed application retains the draft. Graded blanks no longer contribute zero to calculations; explicit missing work and recorded zeros still do.
5. **Image grades.** A separate grade-table reader uses local OCR geometry and score/possible columns or fractions. It never calls the schedule parser. Ambiguous image rows are initially unselected; original images and bounding regions remain available. Empty OCR drafts can retry their stored source. Imported provenance remains accessible after approval.
6. **Funding.** Optional self-described ethnicity/culture, religion and affiliations have skip/clear and Prefer not to say controls. Local matching requires explicit quoted criteria with URLs and capture dates; ambiguity remains unresolved. The Search assistant builds editable terms, searches the saved catalog, compares evidence, and links to existing writing/version controls. Source refresh, save and task creation stay explicit. AI uses typed goals and an allowlisted public-evidence scope; profile values and private opportunity notes are excluded. Sensitive-trait AI use is absent.
7. **Difficulty signals.** Course Overview and Learn share an authored, dated concept editor with optional note and confidence, editing, clearing and easier status. Active notes contribute only to the selected course's local material ranking, with a visible reason. Practice prepares an editable grounded request; review tasks require an explicit save.

## Persistence and boundaries

Schema 32 adds local difficulty, import-preview and provenance tables with course/grade foreign-key cleanup. Course merging updates preview course IDs and invalidates approval baselines. Encrypted archive restoration includes sources, corrections, provenance and sensitive profile values. New records remain local; no new identity or difficulty inference is derived from grades or other profile attributes.

Schedule AI errors retain offline findings, saved reports and inputs. Consent resets on changes to scope/provider/model and after requests. Native validation checks provider/model plus saved goals and roadmap revisions. Diagnostics record provider, model and categorized status (including rejected_400), without response bodies, secrets or source content. No provider-specific request compatibility change was made without reproduction evidence.
