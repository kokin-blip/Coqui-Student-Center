# Student Center 0.6.0 — encrypted synchronization foundation

Milestone 4 replaces staged synchronization payloads with authenticated canonical mutations while preserving the encrypted local profile as the authority.

## Included

- `CanonicalMutationV2` snapshots and tombstones for profile, terms, preferences, availability, courses, tasks, dependencies, and commitments.
- Persistent device UUIDs and hybrid logical clocks, with transactionally bound offline mutations and deterministic scalar/device tie-breaking.
- Element-identity dependency merging with tombstones and review-required conflicts for competing critical dates.
- Transactional pull application: canonical validation and plan regeneration complete before a mutation is marked applied.
- X25519 account-key wrapping plus Ed25519-signed, expiring existing-device approval envelopes, pending-device review, and immediate revocation.
- Self-serve authorized-device listing with explicit revoke/disconnect controls in the desktop account panel.
- Local 24-word recovery and registration of a fresh device identity before synchronization.
- Encrypted, resumable document chunks with manifest substitution defense and SHA-256 verification before cloud completion or local vault installation.
- A native WebdriverIO/Tauri installed-app smoke lane on Windows x64 and Apple Silicon macOS, isolated from production capabilities and data.
- Automated SHA-256 sidecars for NSIS and DMG release artifacts.

## Migration notes

- Database schema advances additively from version 9 to 10.
- Existing canonical data, local vault objects, plans, import history, credentials, and mutation history are preserved.
- Previously queued, never-uploaded local mutations are safely rebased to the registered device identity when encrypted sync is first connected.
- A device with already-uploaded mutations under another identity is rejected instead of silently rewriting history.
- Demo cleanup remains an explicit reviewed action and is not part of this migration.
