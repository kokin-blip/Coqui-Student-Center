# Coqui Student Center 0.10.0

**Pre-release.** The build is ad-hoc signed rather than notarized, the Windows
smoke record has not been filled in, and this has not been through a release
lane. It is published for testing, not as a general upgrade.

Two things a student had to do by hand now happen for them: the term dates
arrive from their school's own registrar page, and their class schedule can be
pasted in as a screenshot instead of retyped. Both land in the same review queue
everything else lands in, and neither writes anything without being approved.

## Setting up meant retyping a schedule that was already on screen

Every student has their timetable somewhere — a class search results page, a
Canvas week view, a phone screenshot. Setup asked them to read it and type it in
again, one course and one meeting at a time.

Now they can paste it. `Ctrl/Cmd+V` with a screenshot on the clipboard imports
it anywhere in the app, drag-and-drop works from onboarding rather than only
inside the import panel, and onboarding has a file picker for it beside the
course builder. The image is encrypted into the vault like any other document
and read on the student's own computer.

Reading it needed the OCR to stop throwing away where each word sat. Tesseract
was already being asked for the format that reports every word's bounding box,
and the parser was reading those numbers and discarding them. A schedule is a
layout: the "9:00" in the left gutter and the "PSY 101" three columns over are
one class, and nothing in the flattened text says so.

With the boxes kept, the reader clusters words into rows, finds the weekday
headers, assigns each block to a day-column by position, and collapses a class
drawn once per column into a single editable weekly pattern. One-row-per-class
lists are read too. A capture it cannot read produces nothing rather than a
guess — that case has a fixture of its own, because a parser that finds
structure in noise is worse than one that declines.

### What real OCR changed

The first version of this passed every test and read **zero** classes off a real
week grid. Its fixtures were token streams written to suit the reader, so they
agreed with it about everything, including the things it had wrong. Installing
Tesseract and running one genuine screenshot through it is what found that.

The fixtures are now real Tesseract output over real rendered screenshots, with
the images committed beside them, regenerated by
`scripts/fixtures/render-schedule-images.py`.

**A block's height is invisible to OCR.** It is a drawn rectangle; only the
words inside it are recognised. So a calendar that prints its hours once down a
left gutter tells you when a class starts and never how long it runs. Fitting
the start from the ruler is possible and is the wrong idea — it yields confident
times quietly fifteen minutes out. The reader requires the time to be printed in
the block, as Google Calendar, Canvas and Apple Calendar all do, and when it is
not it says *which* kind of unreadable it hit: knowing the times are only in the
left column tells a student to try the AI reader, where "nothing found" tells
them nothing.

**Tesseract wants dark text on a light page.** A dark-mode capture comes back as
five words and a row of pipes. Dark PNGs are now inverted before reading, and
the inverted result is kept only when it recognised more, so a page that merely
looked dark cannot be made worse.

**A misread digit is worse than a missing one.** Real OCR read `PSY 101` as
`psy 401` at 60% confidence on the first pass. That still matches a course code,
so it would have produced a real-looking class for a course the student is not
taking. Low-confidence reads now carry a warning naming the code to check.

Two more defects came out of writing the fixtures. A subject code scans as
weekdays — `MAT` is Monday-and-Tuesday under a lenient parse, filing a
Tuesday/Thursday class on Monday — so the days column now has to read *entirely*
as days. And Tesseract emits the meridiem as its own word, so `1:30` and `PM`
arrived separately and an afternoon class parsed as half past one in the
morning, which the waking-hours check then discarded, losing it outright.

## The registrar's calendar was three hand-typed dates

ASU's term dates were entered by hand from `registrar.asu.edu/academic-calendar`
and could only be corrected by editing JSON and shipping a build.

A school can now describe where its calendar lives and how to read that page,
and the app will fetch it. What comes back is a **diff** — added terms, changed
dates, new no-class dates — never a mutation. A changed term date is a critical
academic date and surfaces as an explicit conflict, the same as a Canvas change
does. The same rules drive `npm run calendar:prepare` at build time, and
`npm run calendar:verify` runs in CI beside `catalog:verify`.

The fetch reuses the Canvas client's guards rather than restating them: resolve
the host once, reject it outright if any address is private, pin those addresses
onto the client so DNS cannot be re-pointed between the check and the
connection, refuse redirects and proxies, and cap the body twice.

Registrar pages are not tables. ASU's is a label followed by one date per
session, each on its own line, so the descriptor names patterns rather than a
CSS selector and no HTML parser enters the binary.

### The fixture that was not the page

The first version of this shipped green and did not work. Its fixture was
written from a *description* of ASU's calendar rather than from the calendar,
and the pattern fitted to that reconstruction read the real page as 152 rows
matching nothing — while printing "No differences against the bundled
snapshot", which is precisely what a working refresh prints. Running it once
against the live page is what exposed it.

The fixture is now a saved copy of the real page, and three things about its
actual shape each produced a wrong date before they were handled: a line sitting
where a date belongs is that session's value rather than a new label ("Final
exams / Session A / Last Day of Classes"); a label is the text immediately above
its date, not everything above it; and boundary vocabulary counts only at the
front of a label, because a registrar names a row first and explains it after.
`calendar:prepare` now exits non-zero when it reads rows and matches none of
them, so that particular silence cannot happen again.

## No school could be added without writing code

Everything a school needs is now a descriptor entry: campuses, term dates with
session codes and no-class dates, where the calendar is published and how to
read it, whether a course catalog is readable at all, and the schedule layouts
its screenshots use. Adding a school is a JSON edit that `calendar:verify`
checks.

That gate catches what types cannot. A row pattern is a string as far as serde
is concerned, so a descriptor can parse cleanly and still be unable to read the
page it points at — a pattern that does not compile, or one with no `label`
group, produces a refresh that silently finds nothing, which is exactly what a
working refresh also reports.

ASU's `catalogSource` says `none`, and says why: its class search answers 401 to
anyone anonymous and authenticates through `weblogin.asu.edu`. That stays a
supported state rather than a gap, and the screenshot path is what covers it.

## A pre-filled date did not say where it came from

Term presets now show their session letter, the last day of classes, when finals
start, and any no-class dates — all of which the data already held and the setup
screen was dropping. The panel names the registrar and the date the snapshot was
taken, because "from the registrar" and "from the registrar, in August" are
different claims and only one of them can be checked. Every field stays editable.

## Managed AI could not describe a class

The accepted candidate kinds were `task`, `commitment`, `assignment` and `exam`,
so every schedule extraction came back as an invalid response. The contract now
carries `class_meeting` and `academic_event` with weekdays, a local start and
end, location, component, modality and section number.

The awkward part was evidence. A candidate's evidence must be a literal
substring of the excerpt — that is what stops the model inventing a due date —
and an image has no excerpt. Rather than weaken it, the image never travels
alone: the app OCRs it locally and sends that text as the excerpt with the
picture attached, so the model is asked to group text we already hold. The
substring check is untouched.

The second reading is offered per import from an explicit button, never invoked
on the app's own initiative, and the panel says in a sentence that this sends
the picture and the text read from it off the computer. Skipping it leaves the
app fully usable.

## Verification

157 native Rust tests, 22 UI tests, 47 script tests, 16 contract tests and 49
cloud-service tests pass; every workspace typechecks; `catalog:verify` and
`calendar:verify` are both green.

Both halves were run against reality rather than against their own fixtures,
which is how the two largest defects in this release were found. The calendar
refresh was run against the live registrar page; it reports no differences and
harvests six real no-class dates across three terms. The screenshot reader was
run over real Tesseract output; it reads a real week grid, a Google-style week,
a 3x capture and a class list exactly, and declines the three it cannot read.

Three further defects were found by writing the tests rather than by review: the
two schedule-parsing ones above, and a denial of service in the AI endpoint — Zod's
base64 pattern groups in fours and recurses per group, so the largest legal
image payload overflowed the stack and returned 500 where it meant 400.

A fourth was found before any of this started. `get_document_evidence` selected
fifteen columns and read four past the end of them, so every call failed for any
document that had candidates. The schema version had drifted the same way: the
code moved to 12 while the browser fixtures, the e2e assertion, and the contract
test meant to guard them all still said 11. That guard now derives the number
from the Rust constant instead of restating it, and caught the move to 13
immediately.

**Not covered.** `npm run test:desktop:e2e` does not complete on this machine.
The WDIO variant builds and the harness attaches, but every spec fails with
"Tauri core.invoke not available after 5s" — including the two specs that
shipped in 0.9.2, so this is the local environment rather than a regression
here. The likely cause is the Keychain prompt a freshly ad-hoc-signed binary
raises on first launch, which a headless run cannot answer. CI builds the same
variant and is where these are meant to run. The Windows smoke record is also
outstanding, which is part of why this is a pre-release.

## Known limitations

- **Dark-mode screenshots are not read.** Inverting recovers some captures but
  not all, and the reader declines rather than guessing at the rest. This is
  measured against a committed fixture, not assumed.
- **Week views that print their hours only in a left gutter are not read.** The
  days and courses are recognised; the durations are not knowable from OCR, and
  the reader says so rather than inventing them.
- **Only the academic calendar refreshes.** Course catalogs mostly sit behind a
  login and nothing here defeats one.
- Builds remain unsigned beyond ad-hoc; the updater is still inert.
- ICS `LOCATION` is still unread.

Canvas stub, which never had an image at all.
