# Coqui Student Center 0.10.1

**Pre-release.** Ad-hoc signed rather than notarized, no Windows smoke record,
and the e2e suite still does not complete locally. Published for testing.

0.10.0 shipped two features that could not be reached and four ways to strand a
student with no way forward. This fixes all of it, along with the rest of a
review that returned fifteen findings.

## Two features nobody could use

`refresh_school_calendar` was built, registered, unit-tested — and never called.
The TypeScript wrapper had zero importers, no component rendered a
`CalendarDiff`, and there was no command that could apply one. The diff was
computed and thrown away. The release notes and the README described it as
working.

The six holidays harvested from ASU's registrar had the same shape of problem.
They were shown on the term preset chip and then dropped: the preset handler
copied only the name and the start and end dates, and completing onboarding
never wrote a calendar event. A student read "2 no-class dates" and still got
study blocks scheduled on Thanksgiving.

Both are now wired. Settings has **Check for calendar updates**; what comes back
is a list of proposed changes with the value you have beside the value your
registrar publishes, and nothing is applied until you tick it. Holidays land as
no-class days, which the planner already knew how to honour — that mechanism
existed and had simply never been given any data.

Two rules keep the apply step safe. A change lands only when the stored value
still matches what the diff was computed against, so a date you moved yourself
wins and is reported as skipped rather than overwritten. And a term is matched
by the name it was created with, so a change for one term can never land on
another.

### Why it happened

Both features had passing tests. What neither had was anyone tracing the path
from a click to a stored record. The lesson is in the backlog now: a feature is
not done when its command works, it is done when a student can reach it and
something changes as a result.

## Four dead ends

**Re-pasting a screenshot did nothing.** Approving the classes from a screenshot
shreds the image; pasting that same screenshot again then said "this already
exists in your encrypted vault", named a document whose image had been deleted,
and imported nothing. The duplicate check matched on hash alone. A document is
only a duplicate while its bytes are still there.

**Dotted meridiems dropped every time on the page.** `1:30 p.m.` parsed as
`None`, so it read as half past one in the morning and the waking-hours guard
discarded the class outright. A schedule written that way produced nothing at
all.

**Pasting during onboarding said nothing.** The import worked; the toast and the
review modal it wrote to are not rendered during setup, and the onboarding copy
tells you to paste there. Onboarding now reports its own result.

**"Ask AI to re-read this screenshot" was offered when it could only fail.** It
appeared on documents whose image had been shredded — which happens exactly when
every class is settled, the moment a student is most likely to be reading the
evidence.

## The AI reader now keeps a record of itself

`read_schedule_with_ai` was the one flow that sends a picture of the student's
own screen and the only managed-AI path that logged nothing: no `ai_invocations`
row on success or failure, no onboarding gate, no transaction, and a stable
`source_uid` so pressing the button twice stacked a second copy of the same
classes. It now does what every other managed-AI call already did, and asking
again replaces the pending candidates rather than adding to them.

## Integrity

`extract_document` takes an explicit source instead of calling `is_file()` on a
caller-supplied path. A pasted screenshot has only a basename, so that check
resolved against the process working directory: a file of the same name sitting
there would have been read by OCR while entirely different bytes were encrypted
and hashed, and the evidence would not have described the stored document.

The Rust de-tagger drops HTML comments, which its JavaScript mirror already did.
A comment containing `>` leaked its body into the parsed text as calendar rows —
a divergence between two parsers explicitly claimed to agree, which the shared
fixture happened not to exercise.

The grid reader runs whenever a weekday header row is present. Gating it on the
descriptor meant a school declaring only a list layout lost the grid reader
entirely, which is worse than a school nobody has described. Adding a descriptor
must never remove capability.

## Smaller things

- A screenshot crosses the IPC boundary as raw bytes. It was a JSON number
  array: roughly 100 MB for a 25 MB image, built and parsed twice, per paste.
- Scanned PDFs no longer retain word boxes. The cap was per page, so a
  hundred-page scan held a couple of hundred megabytes of geometry no reader
  ever looks at.
- The drag-over highlight is removed rather than fixed. Tauri leaves
  `dragDropEnabled` on, so the OS takes the drop and the webview never sees an
  HTML5 drag event — the styling could not fire. Dropping still works.
- Dead code from the grid rewrite is gone.
- The e2e calendar assertion exercises the refusal path against a school with no
  descriptor instead of reaching `registrar.asu.edu`, so the suite no longer
  depends on someone else's uptime.

## Verification

162 native Rust tests, 22 UI tests, 47 script tests, 16 contract tests and 49
cloud-service tests pass; every workspace typechecks; `catalog:verify` and
`calendar:verify` are green.

The regressions that matter are pinned rather than described: applying a diff
twice is a no-op and a student's own edit survives it; a shredded screenshot can
be imported again while a stored one still cannot; malformed harvested holidays
are skipped and the good ones reach the planner as fixed constraints; dotted
meridiems are in the golden clock vector.

**Not covered.** `npm run test:desktop:e2e` still does not complete on this
machine — every spec times out waiting for `core.invoke`, including the two that
shipped in 0.9.2, so it is the local environment rather than a regression. The
Windows smoke record is still outstanding.

## Known limitations

Unchanged from 0.10.0: dark-mode screenshots and week views that print their
hours only in a left gutter are declined rather than guessed at; only the
academic calendar refreshes, not course catalogs; builds are ad-hoc signed and
the updater is inert; ICS `LOCATION` is unread.

One worth stating plainly because it is now reachable: a no-class day blocks
self-directed study, not only classes. That is what a student means by a holiday
and matches the existing wording, but a week-long spring break removes that
week's study capacity. Kept deliberately rather than changed quietly.
