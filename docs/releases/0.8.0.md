# Coqui Student Center 0.8.0

Fixes the post-onboarding hang, removes the pressure to enter a schedule during
setup, and takes the expensive work off the startup path.

## Onboarding no longer demands a schedule

- Only the profile step is required: a name and a timezone.
- School and term, courses and class times, and weekly rhythm are all skippable,
  each with an explicit **Skip for now** action.
- The timezone confirmation checkbox no longer resets every time the timezone
  changes. It is pre-confirmed for a value detected from the computer or picked
  from the city list, and is only re-armed for a location-derived guess, which is
  the case that genuinely needs a human check.
- Finishing with no courses is now valid end to end. Previously the interface
  required both a course number and a title, and the backend independently
  rejected a course-less draft.
- Fixed a latent defect: with the schedule step skipped, completion used to
  synthesize a course row with an empty title. It now writes no course at all.
- The last remaining availability day cannot be unchecked, so setup can no longer
  produce a draft the planner would reject.

## A setup checklist on Today

Because setup no longer collects a schedule, Today shows a dismissible checklist
covering the three things the planner needs — a course, class times, and one
assignment or exam — each linking to the screen that adds it, plus a shortcut to
import a syllabus. It hides itself once every item is done, and the dismissal is
remembered locally.

## Loading screens can no longer strand the app

- **This is the reported bug.** When `complete_onboarding` returned a bootstrap
  without a dashboard, the interface set its plan to null and parked on
  "Loading your plan…" forever: there was no retry, no error text, and no bound
  command that could refill it. Completion now re-fetches instead of hanging.
- Both loading screens gained an explicit error state with the underlying message
  and a retry button.
- A 15-second watchdog makes a slow start interactive without cancelling it, so a
  late-resolving startup still heals the screen.
- A bounded auto-recovery pass (three attempts) covers any other route to a null
  dashboard before surfacing a manual retry.

## Startup and responsiveness

- The OCR readiness probes launched two subprocesses — including a second copy of
  the app binary — during setup, before the window was created, costing up to ten
  seconds on every launch. Discovery is now filesystem-only and the probes run on
  a background thread after the window is shown, reporting through a new
  `checking` state and a `studentcenter:ocr-status` event.
- `app_initialize`, `complete_onboarding`, `get_dashboard`, `search_institutions`,
  and `get_institution_setup_options` moved from synchronous commands, which run
  on the main thread and freeze the webview, to `spawn_blocking`.
- The 702 KB / 6,243-entry institution directory was re-parsed on every keystroke
  of the school search. Both bundled resources are now parsed once per process.
- `complete_onboarding` holds a single lock across its write and read-back, so the
  returned payload always reflects the commit that just happened and cannot
  interleave with the reminder or Canvas workers.

Measured on this machine: cold first run reached a responsive window in **1.2 s**,
restart in **0.6 s**.

## Verification

- 81 native Rust tests, 11 UI contract tests, 2 shared-contract tests, and 15
  cloud-service tests pass.
- Native WebdriverIO first-run smoke passes, including a new case that completes
  setup from a name and timezone alone and asserts the returned dashboard is not
  null and that no placeholder course was created.
- Windows silent install, cold launch, restart, and silent uninstall pass. The
  pre-existing encrypted profile was moved aside and restored with an identical
  SHA-256.
